# Audit — September 2026

A full pass over the repository looking for defects that the toolchain does not
catch. Worth stating up front: on the commit this audit started from, `tsc -b`,
`eslint`, `vitest` and `vite build` all passed clean. Every bug below survived a
green pipeline, which is the interesting part — they are runtime, visual and
concurrency defects, and no amount of stricter linting would have found them.

Each entry says what was wrong, why it mattered, and how it was fixed. Where a
fix is pinned by a test, the test is named.

---

## 1. Five competing page-width systems

**The bug.** Routed pages used one of five different width-and-gutter
conventions:

| System | Max width | Gutter at `lg` | Pages |
|---|---|---|---|
| `.page-shell` (CSS class in `index.css`) | 1280px | 32px | 9 |
| `PageContainer` (wrapped Tailwind `container`) | 1400px | 64px | 6 |
| `PageContainer` + a nested `max-w-7xl` | 1280px | 64px | 3 |
| Ad-hoc `p-6 lg:p-10 max-w-7xl` | 1280px | 40px | Roadmap |
| No wrapper at all | — | — | Landing, Login, Signup |

`PageContainer` wrapped Tailwind's `container` utility, which already carries
`padding: 2rem` from `tailwind.config.js`, and then added `px-4 md:px-8` on top
of it. So those pages got double padding *and* a wider cap than everything else.

**Why it mattered.** The content edge moved 32px horizontally as you navigated
between Dashboard, Analytics, Roadmap and Courses, and the maximum content width
changed by 120px. On a wide monitor this reads as the layout twitching on every
route change.

**The fix.** `PageContainer` is now the single width primitive — four named
widths (`narrow` / `default` / `wide` / `full`) over one gutter scale
(`px-4 sm:px-6 lg:px-8`) and one vertical rhythm. `.page-shell` was left in place
but now mirrors that geometry exactly, with a comment on both sides saying so, so
the ~9 pages using the CSS class did not all need touching. Roadmap and
SharedCourse were moved onto the shared scale.

## 2. Lesson text was white-on-white in light mode

**The bug.** `prose-invert` was applied unconditionally in `MemoizedMarkdown`,
`ChatMessage`, `FeedbackPanel` and `CodingWorkspace`.

**Why it mattered.** `prose-invert` is Tailwind Typography's *dark background*
variant. The app's default theme is light (`--background: 0 0% 97%`), so lesson
bodies, AI chat replies and interview feedback rendered near-white text on a
near-white surface — the core reading experience of the product, unreadable for
any user who had not switched to dark mode.

**The fix.** `dark:prose-invert` in all four.

## 3. Code blocks lost their syntax colouring

**The bug.** `CodeSnippet` called `getLineProps({ line, key: i })` and
`getTokenProps({ token, key })`. `prism-react-renderer` returns whatever you pass
in, so `key` came back *inside* the props object and was then spread into JSX —
which is the React warning that was visible in the `LessonRenderer` test output.
Separately, the explicit `className="table-row"` sat *after* the spread, so it
overwrote the `className` Prism returns.

**Why it mattered.** The className Prism returns is what carries the token
colours. Overwriting it renders every code block as flat monochrome text.

**The fix.** `key` is passed directly to JSX and no longer handed to the prop
getters; the returned `className` is destructured out and merged with `clsx`
rather than replaced.

## 4. Search wiped the rest of the query string, one entry per keystroke

**The bug.** `TopNavigation` called `setSearchParams({ search: val })`.

**Why it mattered.** Two things. Passing a fresh object replaces the entire query
string, so any active filter, sort or tab param was silently dropped the moment
the user typed. And the default `push` behaviour created a history entry per
keystroke, so Back walked backwards through the search term one character at a
time instead of leaving the page.

**The fix.** Merge into the existing `URLSearchParams` and pass
`{ replace: true }` — typing is not navigation.

## 5. A gateway error replaced itself with a TypeError

**The bug.** The axios response interceptor ended with
`error.response.data.error = msg`.

**Why it mattered.** That assumes the response body is a mutable object. A Render
cold-start or a 502 returns an HTML body (a string primitive), and a 204 returns
none at all. Under ES-module strict mode, assigning a property onto either throws
`TypeError` *inside the interceptor* — so the user saw a confusing internal error
instead of "the server is waking up", exactly during the cold start the README
warns about.

**The fix.** Type-check the body, mutate it only when it is an object, and
otherwise replace `error.response.data` wholesale with a normalized
`{ error: string }`.

## 6. Two locks sharing one sessionStorage slot

**The bug.** Both the axios dedup interceptor and the SSE flow in
`useLessonProgress` wrote to `sessionStorage['active_generation_job']`, with
different value shapes (`{key: "post:/generate:{...}"}` vs
`{key: "lesson_gen_<courseId>_<lessonId>"}`).

**Why it mattered.** Each silently clobbered the other's lock. A POST to a
`/generate` endpoint during an active lesson stream overwrote the stream's lock,
and the stream's `finally` block then cleared the POST's — defeating the
duplicate-request guard in both directions.

**The fix.** The interceptor moved to its own namespaced key.

## 7. Users were served fabricated course content during a provider outage

**The bug.** The mock-response fallback in `aiRouter` was guarded by
`chain.length === 0 && !process.env.GEMINI_API_KEY`.

**Why it mattered.** This is the worst one found. `chain` is filtered by circuit
breaker state, so on a Groq-only or OpenRouter-only deployment both halves of
that condition become true the moment the breaker opens — a *transient provider
outage*. The router then returned the hardcoded JSON-basics placeholder course
as though it were a real generation. Users got silently fabricated educational
content instead of an error.

**The fix.** The mock path is a local-development affordance and now depends on
configuration only, never on runtime health: `hasNoConfiguredProvider()` returns
true only when no provider key is set at all.

Pinned by `an open breaker on a Groq-only deployment does not trigger the mock path`.

## 8. The last-resort chain pointed at a provider that might have no key

**The bug.** When every breaker was open, all four router entry points fell back
to a hardcoded `[{ provider: gemini, model: "gemini-2.5-flash" }]`.

**Why it mattered.** That both ignores the breaker and guarantees a 401 on any
deployment that does not happen to use Gemini.

**The fix.** `resolveChain()` falls back to whichever providers are actually
configured, breaker state relaxed, so an expired cooldown still gets one honest
attempt.

## 9. Healthy providers benched for answering a bad prompt

**The bug.** Every `catch` in the router called `circuitBreaker.onFailure()`
unconditionally, including for 400/401/403 responses and schema-validation
failures.

**Why it mattered.** A provider that is up and responding, but was handed a
prompt it answered in the wrong shape, accrued failures toward the threshold and
got taken offline for the full cooldown. Availability and correctness are
different signals.

**The fix.** `countsAgainstProviderHealth()` filters client errors and validation
failures out of the breaker's view. They still fail the request; they just do not
count as the provider being down.

## 10. A timer leak, and streams killed mid-flight

**The bug.** `executeWithTimeout` created two timers — one to abort, one to
reject — and cleared only the first.

**Why it mattered.** The reject timer stayed armed for the full 20s after a fast
success, holding the event loop open (this is the source of Jest's "did not exit
one second after the test run"). Worse: for the two *streaming* callers, this
function resolves as soon as the stream object exists, so the abort timer then
fired 20 seconds later and killed a stream that was healthily mid-generation.

**The fix.** A single `finally` disarms the timer whichever way the race
resolves, and abort now happens only on the timeout path.

## 11. `parseRobustJson` choked on the most common model output

**The bug.** Code fences were stripped *before* `.trim()`, using
`/\n?```$/`.

**Why it mattered.** That regex requires the string to end at the fence. Gemini
and Groq both routinely emit a trailing newline after the closing fence, so the
fence survived into `JSON.parse` and the generation failed — then retried, then
failed over to the next provider, all for a stray `\n`.

**The fix.** Trim first, then extract. It now also handles a fenced block wrapped
in prose ("Here is the JSON you asked for:"), and attaches the underlying parse
error as `cause` so a malformed payload is debuggable from logs.

Pinned by five cases in `describe("parseRobustJson")`.

## 12. Streak logic: duplicated, UTC-based, and no longest streak

**The bug.** Three defects in one area.

- The logic existed twice — in `analyticsController.recordStudyTime` and inline
  in `courseController.updateLesson` — with subtly different code in each.
- Both derived "today" from `new Date().toISOString().slice(0, 10)`, a **UTC**
  calendar day.
- `dashboardController` reported `longest: userDoc?.studyStreak` — the current
  streak under a different label.

**Why it mattered.** For a user in IST (UTC+5:30), everything before 05:30 local
counts as the previous UTC day. A session at 01:00 IST on the 11th is 19:30 UTC
on the 10th, so a late-night study session either failed to extend the streak or
double-counted a day. Given where this project's users are, that is not an edge
case. And the "longest streak" card dropped to 0 every time a streak broke,
which is the exact moment a user most wants to see it.

**The fix.** One `services/streakService.js` with pure, clock-injectable
functions; a persisted `longestStreak` high-water mark on the `User` model; and
an optional per-user `timezone` (falling back to `APP_TIMEZONE`, then UTC).

Pinned by nine cases in `describe("streakService")`, including the IST midnight
boundary and a leap-year day rollover.

## 13. Concurrent activity lost XP

**The bug.** `recordActivity` did a read-modify-write:
`user.xp = (user.xp || 0) + xpToAdd; await user.save()`.

**Why it mattered.** Finishing a lesson and its quiz fires two `recordActivity`
calls in quick succession. Both read the same starting XP and the second `save()`
overwrote the first — silently losing the award. `checkAndUnlockAchievements`
made this worse by mutating the same document in between.

**The fix.** XP is now a server-side `$inc`. Badge unlocks are a separate `$push`
guarded by `{ "achievements.badge": { $ne: badge } }`, which makes a double
unlock impossible even under a genuine race. `findNewlyUnlockedAchievements`
computes and returns; it no longer mutates.

## 14. Every test suite booted a MongoDB

**The bug.** `tests/setup.js` was wired via `setupFilesAfterEnv`, so all eleven
suites started a `MongoMemoryServer` — including the ones that touch no database
at all.

**Why it mattered.** A ~90MB `mongod` download on any cold machine, and a hard
failure on any network that cannot reach `fastdl.mongodb.org`, for tests that
never needed it.

**The fix.** Two Jest projects. `npm run test:unit` runs pure logic with no
database and no network (25 tests, 1.7s); `npm run test:integration` keeps the
supertest suites. CI runs them as separate steps so a logic regression fails in
seconds rather than after the binary download.

## Smaller fixes

- **`useAutoScroll`** only scrolled while `sending` was true. The assistant's
  reply arrives *after* that flips false, so the last message sat below the fold.
  Now follows the transcript whenever it grows — but only when the user is
  already near the bottom, so scrolling up to re-read is not yanked back down.
- **`useClipboard`** called `navigator.clipboard.writeText` unguarded. That API
  is `undefined` outside a secure context (plain http on a LAN IP, older
  WebViews), so every copy and share button reported failure. Added a
  `document.execCommand` fallback and cleaned up the reset timer on unmount.
- **`useInterviewTimer`** depended on the whole `activePrep` object, so every
  React Query refetch tore down and rebuilt the interval, dropping the partial
  second each time. The clock drifted slow. Now keyed on `_id` and `status`.
- **`Sidebar`** used `layoutId="sidebar-active"` in both the main nav list and
  the account list. Framer Motion treats a shared `layoutId` as one element.
- **`TopNavigation`** labelled every account "Pro Member", including signed-out
  guests.
- **`CodeSnippet`** had `className="flex gap-1.5 hidden sm:flex"` — `hidden` wins
  at every width, so the leading `flex` was dead weight.
- **`PERFECT_QUIZ_SCORE`** replaces an unexplained literal `5` that appeared in
  both the achievement query and the XP bonus.

## Known, not fixed

Listed so they are not mistaken for oversights.

- **`dashboardController` loads every lesson on every request.** It populates
  modules → lessons across all of a user's courses to count completions. That
  should be an aggregation pipeline; it will get slow at a few hundred lessons
  per user.
- **`overallCompletion` is course-level, not lesson-level.** It reports
  `coursesCompleted / coursesCreated`, so a user 90% through one course reads as
  0%.
- **Main bundle is 744KB (226KB gzipped).** `html2pdf` (736KB) and `jspdf`
  (399KB) are lazily chunked, but the entry bundle is still large.
- **Theme application is duplicated** between `useAuth.tsx` and
  `SettingsPage.tsx` — the same `classList` manipulation written twice.
- **`embedder.cosineSimilarity` truncates to the shorter vector.** If the corpus
  is embedded locally (256-dim) and queries with OpenAI (1536-dim), it silently
  compares the first 256 dimensions instead of erroring.
- **`body::before` grid overlay** uses `rgba(255,255,255,0.05)`, which is
  invisible against the light theme's `0 0% 97%` background. Decorative only.
